# Bookshelf API

TypeScript client for the Bookshelf API API, generated by Emit-Kit. Files under `src/` other than
`src/custom/` are overwritten on every generation run.

## Install

```sh
npm install @acme/petstore-sdk
```

## Usage

```ts
import { BookshelfApiClient } from "@acme/petstore-sdk";

const client = new BookshelfApiClient({ baseUrl: "https://api.example.com" });
```

## Base URL

Requests go to `https://api.bookshelf.example.com/v1` unless `baseUrl` is passed.

## Authentication

Credentials are set through the `AuthOptions` fields in `src/client.ts`. Each field exists only when
the API declares a matching scheme: `apiKey` for API key schemes, `bearerToken` for HTTP bearer,
OAuth2 and OpenID Connect schemes, and `basic` for HTTP basic. Each operation sends only the
credentials of the schemes in its own security requirement, so an operation with no requirement
sends none. When the requirement lists alternatives, the request sends one of them: the first whose
credentials are all set, preferring one that does not put an API key in the URL. An API key is sent in the header, cookie or query parameter that its scheme declares. A
request carries one API key: the first header or cookie scheme the operation names, or else its
query scheme. Other schemes are not mapped. Set them with a custom `fetch`.

## Errors

Non-2xx responses throw an `ApiError` subclass: `BadRequestError` (400), `UnauthorizedError` (401),
`ForbiddenError` (403), `NotFoundError` (404), `ConflictError` (409), `RateLimitError` (429) or
`ServerError` (5xx). Other statuses throw a plain `ApiError`. Each error carries `status`, `body`
and `headers`.

429 and 5xx responses are retried twice by default. Set `maxRetries` to change that. Only requests
that are safe to repeat (GET, HEAD, PUT, DELETE and OPTIONS) or that send an `Idempotency-Key` header
are retried. A `Retry-After` header sets the wait, up to 30 seconds. Otherwise the wait grows
exponentially.

```sh
npm install
npm run build
```
